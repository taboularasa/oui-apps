# ADR 0001: Select the frontend technology stack

- **Status:** Accepted
- **Date:** 2026-08-13
- **Decision owners:** OUI maintainers

## Context

OUI is a configurable TypeScript frontend framework. It is given:

1. a valid application intermediate representation (IR) produced by an external compiler;
2. a generated Go Backend for Frontend (BFF) conforming to service contracts referenced by the IR; and
3. application and deployment configuration.

OUI must turn those inputs into a complete frontend that demonstrably conforms to the IR.

Ontology storage and reasoning, canonical specification parsing, domain-to-UX inference, IR production, BFF generation, and infrastructure definition are upstream concerns. OUI begins at the application IR.

Customer deployments are standardized around:

- Render as the PaaS;
- a Go BFF;
- a TypeScript OUI frontend;
- Buf, Protobuf, and Connect service contracts; and
- a canonical specification bundle from which the BFF and application IR are compiled.

The selected frontend stack therefore needs to support:

- an IR-driven application and interaction runtime;
- generated, strongly typed routing and BFF bindings;
- a large reusable vocabulary of interaction patterns;
- forms, collections, workflows, decisions, evidence, and permission-aware actions;
- accessible behavior across keyboard, pointer, touch, and assistive technologies;
- build-time code generation and static deployment;
- runtime theming without coupling the IR to a styling implementation;
- browser-level conformance testing; and
- long-term maintenance across many customer deployments.

The stack was evaluated as of August 13, 2026.

## Decision

OUI will use a client-first React architecture:

| Concern                        | Selection                                                 |
| ------------------------------ | --------------------------------------------------------- |
| Language                       | TypeScript 7                                              |
| UI runtime                     | React 19.2                                                |
| React optimization             | React Compiler 1.0                                        |
| Build system                   | Vite 8                                                    |
| Routing                        | TanStack Router v1                                        |
| Server state                   | TanStack Query v5                                         |
| BFF transport                  | Connect-ES v2 and Protobuf-ES v2, generated by Buf        |
| Accessible primitives          | React Aria Components                                     |
| Forms                          | TanStack Form                                             |
| Tables and large collections   | TanStack Table and TanStack Virtual                       |
| Complex interaction lifecycles | XState v5, used selectively                               |
| Styling                        | Tailwind CSS 4 with semantic CSS custom-property tokens   |
| Component development          | Storybook 10 with React and Vite                          |
| Unit and browser tests         | Vitest 4 Browser Mode using Playwright                    |
| End-to-end tests               | Playwright                                                |
| Accessibility automation       | Playwright with axe-core                                  |
| Workspace                      | pnpm workspace on Node.js 24 LTS                          |
| Deployment                     | Render Static Site communicating directly with the Go BFF |

## Architecture

```text
Application IR --------------------> Generated OUI configuration
                                            |
Protobuf and Buf contracts --------> Generated Connect-ES clients
                                            |
                                            v
                                      OUI React runtime
                                            |
                 +--------------------------+--------------------------+
                 |                          |                          |
          TanStack Router          Interaction registry       Semantic design system
                 |                          |                          |
                 |                  TanStack Form/XState       React Aria Components
                 |                                                     |
                 +----------------> TanStack Query <-------- Connect runtime
                                                              |
                                                              v
                                                            Go BFF
```

The frontend will be built as a static application. It will communicate directly with the Go BFF rather than introducing a JavaScript server between the browser and BFF.

## Rationale

### React

React has the strongest combination of accessible headless component systems, typed routing and data libraries, state-machine support, design-system tooling, browser testing, ecosystem maturity, and maintainability for a large configurable interaction framework.

React Compiler provides production-ready build-time optimization while allowing OUI components to remain declarative.

### Vite

OUI is a frontend framework and generated static application, not an additional full-stack server. Vite supplies a fast development environment, application and library builds, plugin APIs suitable for generated inputs, and static output that can be deployed directly on Render.

Using Vite also aligns the application build, Vitest, and Storybook around the same transformation pipeline.

### TanStack Router

TanStack Router is explicitly client-first and treats the route tree as an application contract. Its typed route parameters, validated structured search state, code-based route generation, preloading, boundaries, and code splitting fit compiler-produced applications.

The upstream compiler can generate the route tree from the IR without requiring file-system routing to become canonical.

### TanStack Query

TanStack Query is transport-independent and can wrap generated Connect clients. It owns remote BFF state, including caching, deduplication, freshness, invalidation, retries, pagination, and network recovery.

It will not own form state, URL state, or complex local interaction lifecycles.

### Connect-ES and Protobuf-ES

Connect and Protobuf preserve the generated, schema-first contract between the TypeScript frontend and Go BFF. OUI will use generated clients and a small shared transport layer for authentication, tracing, locale information, normalized errors, idempotency, and test transports.

OUI will not add a second general API abstraction such as GraphQL or an untyped REST client by default.

### React Aria Components

React Aria Components provides a broad set of style-free components with built-in keyboard, touch, pointer, screen-reader, focus-management, internationalization, collection, selection, and validation behavior.

OUI will wrap these primitives behind its own semantic component API. IR definitions and interaction patterns must depend on OUI concepts rather than React Aria component names or properties.

### TanStack Form

TanStack Form provides typed, composable, dynamic, synchronous, and asynchronous validation suitable for generated forms. Validation meaning remains defined by the IR and BFF contracts; TanStack Form executes and presents it.

### XState

XState will be used only for interactions that are naturally state machines or actors, such as resumable workflows, long-running commands, compensation, multi-step decisions, and reconnect behavior.

State ownership is divided as follows:

| State                             | Owner           |
| --------------------------------- | --------------- |
| Remote BFF state                  | TanStack Query  |
| URL and navigation state          | TanStack Router |
| Form state                        | TanStack Form   |
| Complex interaction lifecycle     | XState          |
| Small local visual state          | React           |
| Theme and stable runtime services | React context   |

### Styling and theming

Tailwind is an internal design-system implementation tool. It is not part of the application IR.

The following constraints apply:

- the IR must not contain Tailwind class names;
- customer configuration supplies semantic tokens rather than utility classes;
- runtime themes are expressed through CSS custom properties;
- published OUI packages include their required compiled CSS;
- accessibility modes and density are token-level concerns; and
- interaction behavior must not depend on a theme.

This keeps presentation replaceable without changing the IR.

### Testing

IR conformance is a primary framework requirement rather than a secondary testing concern.

- Vitest Browser Mode tests patterns and components in real browsers.
- Playwright tests complete generated applications, routes, BFF interactions, accessibility trees, and visual behavior.
- axe-core catches automatically detectable accessibility failures.
- Manual keyboard, screen-reader, zoom, reflow, reduced-motion, high-contrast, and touch testing remains required.

## Rejected alternatives

### Next.js

Next.js 16.3 is a capable full-stack React framework, but its server-oriented capabilities duplicate the generated Go BFF. Using it would introduce an unnecessary JavaScript server, split responsibility for data loading and mutations, and add deployment complexity without a corresponding benefit for authenticated operational applications.

The rejected topology is:

```text
Browser -> Next.js server -> Go BFF
```

The selected topology is:

```text
Browser -> Go BFF
```

### TanStack Start

TanStack Start adds server rendering, server functions, server routes, and middleware that OUI does not need. It was also still documented as a release candidate at the time of this decision. TanStack Router supplies the relevant client-side application model without adding another server.

### React Router v8

React Router v8 is stable and is the preferred fallback. TanStack Router was selected because its generated route contract, structured and validated search parameters, client-first architecture, and TanStack Query integration align more directly with IR-generated applications.

This decision should be revisited if TanStack Router's generated type graph causes unacceptable TypeScript performance or scaling problems.

### Base UI

Base UI 1.7 is a credible stable alternative for unstyled accessible primitives. React Aria Components was selected because its broader component coverage, internationalization, adaptive interaction behavior, and collection model better fit a cross-domain application framework.

OUI should avoid routinely combining multiple primitive systems because doing so risks inconsistent focus, overlays, keyboard handling, and form behavior.

### Redux as a default

OUI has clear owners for remote, URL, form, workflow, and local state. A global Redux store would duplicate those responsibilities. It may be introduced only if a concrete, otherwise-unmet cross-cutting state requirement appears.

### GraphQL

The frontend and Go BFF already share generated Protobuf and Connect contracts. Adding GraphQL would duplicate the contract and transport model.

## Consequences

### Positive

- The browser communicates directly with the generated Go BFF.
- The frontend can be deployed as static assets on Render.
- Generated Protobuf types survive from the BFF contract into frontend data access.
- Routes and URL state can be generated from the IR with strong typing.
- OUI can build a large semantic component vocabulary over an accessibility-focused primitive layer.
- The application, component catalog, and browser tests share the Vite ecosystem.
- Customer theming remains independent of IR semantics.
- State ownership is explicit.
- The framework can test IR conformance in real browsers.

### Negative

- OUI must build and maintain its own semantic component and interaction-pattern layer.
- React Aria Components has more structural APIs than simpler primitive libraries.
- Deeply generated TanStack Router types may require performance monitoring.
- TanStack Query, Form, Router, and XState require clear boundaries to avoid overlapping abstractions.
- Static deployment means SSR is not available by default.
- Tailwind must be encapsulated carefully so generated or runtime IR content does not depend on class scanning.
- Automated accessibility testing cannot replace manual assessment.

### Neutral constraints

- Domain-specific behavior must remain in the IR and BFF rather than leaking into framework components.
- OUI packages must wrap third-party libraries so the application IR is not coupled to their APIs.
- A later need for public, SEO-sensitive surfaces should be solved by a separate rendering adapter or a new ADR rather than by turning the core OUI runtime into a full-stack framework preemptively.

## Validation plan

Before treating the stack as irreversible, build a vertical slice containing:

1. a generated route tree with typed path and search parameters;
2. a Connect query and command against a test Go BFF;
3. an IR-defined collection and detail interaction;
4. an IR-defined form with synchronous and BFF validation;
5. an evidence-backed decision interaction;
6. a long-running command lifecycle;
7. theme and density switching;
8. keyboard-only and screen-reader-compatible operation;
9. Vitest browser tests for semantic components; and
10. Playwright conformance and accessibility tests for the generated application.

The decision should be reconsidered if the vertical slice demonstrates that:

- generated route typing does not scale;
- React Aria cannot support the required semantic composition;
- Connect browser behavior cannot satisfy required streaming or error semantics;
- static deployment prevents a required interaction model; or
- the selected state libraries cannot maintain clear ownership boundaries.
